# Team 消息及时投递与错误终态

普通消息与最终回执现在使用 Pi 的实际 steering 路由。运行中的 parent 不再等整段工具循环结束才接收结果，空闲普通消息仍不触发任务。

## 背景与结果

历史会话中，同级文件冲突消息迟到 25 分 16 秒，自动最终回执最长迟到 2 小时 37 分 49 秒。普通消息的显式 `triggerTurn:false` 绕过了 Pi steering；最终回执则排在 followUp 队列中。发送者继续普通工具工作时，合并缓冲也没有自动 flush。

修复省略普通消息的 triggerTurn，将 FINAL_ANSWER 改为 steer，NEW_TASK 保留 followUp。25 ms 合并窗口自动发送，非 send 的 team 动作与 root turn_end 可提前 flush；只有实际投递后才通知等待者。单个收件人失败不丢弃其他批次消息；shutdown 清理定时器与缓冲。

模型 error/aborted 响应即使正常 resolve prompt Promise，也分别记录 failed/cancelled，保留错误与单次终态。重试恢复后的成功响应仍完成。

## 边界与风险

Steer 仍等待当前请求/工具到达安全边界；25 ms 是合并窗口，不是端到端响应时限。没有调整并发额度、增加协议类型或修改 Pi 核心/Rust。没有执行真实模型/TUI E2E，也未运行 Cargo、重建或热替换安装中的二进制。已有会话不会自动使用新代码。
