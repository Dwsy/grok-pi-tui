# Issue: Team 消息及时投递与错误终态

## Goal

让普通 team 消息和最终结果及时进入活跃接收者的 Pi steering 队列，保留 idle 不唤醒和 follow-up 下一任务语义，并准确记录模型错误终态。

## 背景/问题

核对 2026-11-10 的主会话 `01a1c36c-9763-731a-9bc4-69a752a9916c`、43 份子会话及当前 Pi 1.5.0：同级冲突消息从发送到目标日志相隔 25 分 16 秒，自动最终回执最长相隔 2 小时 37 分 49 秒。

`team_send_message` 显式传 `triggerTurn:false`，使 Pi 绕过 steering 队列；最终回执使用 followUp，要等父级整段工具循环结束。合并缓冲没有定时投递上限。Pi 将模型失败编码为 assistant `stopReason:error` 时，prompt Promise 仍可能正常 resolve，runtime 因此错误记录 completed。

工作区已有未提交修改。实施前已保存所涉及文件的副本；不得覆盖现有 UI、并发设置和上下文继承修改。

## 验收标准 (Acceptance Criteria)

- [x] 活跃接收者的普通消息进入真正的 steer 队列；idle 普通消息不启动任务。
- [x] 活跃 root / parent 的 FINAL_ANSWER 不等待整段工具循环结束；idle / queued parent 的恢复和并发限制保持有效。
- [x] 连续发送仍可合并去重；即使发送者没有后续 team 动作，缓冲也自动投递。
- [x] followup 仍表示下一项任务；工具说明明确收尾/纠偏应使用普通消息。
- [x] 模型 error/aborted 不能记录 completed；保存错误信息且每次运行只产生一次终态。
- [x] 覆盖真实 Pi API/agent loop 的离线回归，且不访问模型服务。
- [x] V2/runtime 相关测试、扩展源码类型检查、文档及 diff 检查通过，已知基线限制单独记录。

## 关键决策

| 决策 | 理由 |
|------|------|
| 普通消息省略 triggerTurn | Pi 运行中按 steer 路由，idle 时仅追加，不需自行猜测状态 |
| NEW_TASK 保留 followUp，FINAL_ANSWER 改 steer | 下一任务与当前依赖结果的时机不同 |
| 使用短定时合并窗口 | 保留同批去重；不再无限等待另一项 team 操作 |
| 不改 Pi 核心和 Rust 协议 | 官方 API 已能表达所需语义，变更限定于扩展 |
