# Issue: 拆分高价值 Pi 扩展模块

## Goal

将 `rollback`、`shortcut-manager`、`auth`、`loop` 四个高价值的单文件 Pi 扩展按职责拆分为可注入的 TypeScript bundle，保持现有运行时行为与 Rust/Pi 注入契约。

## 背景/问题

这些扩展均超过 500 行，且由 Rust `include_str!` 注入临时文件。拆分时若 Rust 注入器未同步物化全部相对导入，会在 Pi 启动时因模块缺失而失败；因此每个扩展都必须同时拆分 TypeScript、重写对应注入器、更新 `source_path()` 调用点，并完成隔离加载验证。

## 验收标准 (Acceptance Criteria)

- [ ] 四个目标扩展均按单一职责拆分，入口文件只保留注册与编排。
- [ ] Rust 注入器物化其 `index.ts` 相对导入的完整传递闭包，并在进程生命周期内保活临时目录。
- [ ] `grok-pi.rs` 使用 bundle 的 `source_path()`，不引用过期的单文件路径 API。
- [ ] 每个扩展通过本扩展 TypeScript 诊断筛查、隔离 `pi -ne --mode rpc --extension` 加载与对应 Rust 注入器测试。
- [ ] 最后完成 `grok-pi` bin check、`git diff --check` 与范围审查。

## 关键决策

| 决策 | 理由 |
|------|------|
| 仅拆分 >500 行、职责边界已清晰的扩展 | 避免为短小单文件引入无收益的模块边界。 |
| 显式 `.ts` 相对导入 | 与已验证的 bash/btw/remote-tui bundle 约定一致。 |
| 不改扩展公共行为或产品契约 | 本任务是可维护性重组，不借机扩大功能范围。 |
