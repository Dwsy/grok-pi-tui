# Grok Native TUI × Pi Feature Matrix


**Minimum Pi version: 0.80.10** (system `pi` / `@earendil-works/pi-coding-agent`). `pi-main` is an optional git submodule, not required at runtime.

Status definitions: **Native** = implemented by a Grok Pager component; **Adapted** = Pi semantics converted and projected into a Grok native component; **Boundary** = Pi RPC does not expose it or it is bound to a Grok product backend, deliberately not implemented.

## Agent and Streaming Semantics

| Pi feature | Status | Mapping |
|---|---|---|
| Prompt | Adapted | ACP prompt → Pi `prompt` |
| Mid-turn send now | Adapted | Composer send-now → locally held `Steering` lane row (same isolated queue as follow-ups), forwarded to Pi as `steer` at the assistant `message_end` safe-point flush — identical observable delivery timing, but the row stays removable/editable until then; rows still held at settle dispatch as the next turn's prompt. A pending row can also be sent immediately via `x.ai/queue/interject`; edit-then-send uses the row version. Rows discovered only in Pi's external queue remain read-only because stock RPC cannot remove them atomically. |
| Follow-up queue | Adapted | Active-turn client prompts and extension `sendUserMessage(..., { deliverAs: "followUp" })` calls stay in an adapter-owned isolated queue until dispatch; extension steers (`deliverAs: "steer"`) are held in the same isolated queue's steering lane instead of interjecting immediately. Promoted rows re-enter Pi with RPC source; `queue_update` messages that bypass interception are mirrored in a separate external lane. |
| Abort | Adapted+Boundary | ACP cancel synchronously clears adapter-owned client/extension rows and completes their waiters, drops extension continuations emitted while cancellation is active, then fire-and-forget notifies Pi `abort` (`abort_bash` for Bash). A `get_state` settle probe reopens dispatch only after Pi is idle. Stock Pi external rows remain an RPC boundary because 0.81.1 exposes no `clear_queue`. |
| Text stream | Adapted | `message_update` → AgentMessageChunk |
| Thinking/reasoning stream | Adapted | `message_update` → AgentThoughtChunk |
| Tool start/update/end | Adapted | ACP `ToolCall`/`ToolCallUpdate` |
| Pi Bash background task / Send to Background | Native+Adapted | `grok-pi` private Bash extension holds foreground and initial background Bash subprocesses; foreground reuses Pi `createBashToolDefinition` output/rendering semantics. Pager native Send to Background transfers control via `x.ai/terminal/background` using a controlled temp file keyed by `toolCallId` to the **same** subprocess, then projects to the existing `x.ai/task_*` card; native task-card kill uses `x.ai/task/kill` over the same control channel (`op:kill` + published `runningTaskIds`); `is_background` + `description`, `get_task_output` / `wait_tasks` / `kill_task` remain usable. Foreground Bash auto-promotes after the shared configurable max-wait threshold (default 4.5 min), and each blocking task wait is capped to the same threshold so a still-running task yields a fresh agent turn instead of holding the prompt cache past TTL. `0`/negative disables both behaviors. Terminal state is published out of band on the private `__pi_grok_bash_task__` status channel so it survives streaming, ESC, and a cleared follow-up queue; the conversation bridge message still wakes the model. The adapter mirrors task lifetime, projects each terminal state exactly once across both channels, and settles tasks orphaned by a Pi child exit as `signal: session_restart` (row leaves the running filter, no new failure block). |
| Pi subagents | Native+Adapted | F2 `[ui].pi_subagents` is default on and restart-required. V1 keeps the built-in Pi child `AgentSession`, native `SubagentBlock`/Tasks Pane/child `AgentView` projection, product-isolated `.grok-pi/agents/*.md` + `~/.grok-pi/agents/*.md` definitions, history/wait/cancel, and parent→child follow-up/steer. Optional V2 (`PI_GROK_SUBAGENTS_V2=1`) adds Codex-inspired `/root/...` paths that are stable within the current root Pi session, plus `spawn_team_agent`, queue-only `team_send_message`, triggering `team_followup_task`, `team_wait`, `team_list`, `team_interrupt`, nested spawn, and automatic `FINAL_ANSWER` return to the parent. `spawn_team` loads project `.grok-pi/teams/*.json` > global `~/.grok-pi/teams/*.json` > bundled `research`/`implementation`/`review` presets. V2 semantic messages use `pi-grok-team-message/v2`; UI-only `pi-grok-subagent/v1` remains bounded to lifecycle entries and does not carry progress/child deltas. Completed agents become `IDLE`; reactivation preserves the Pi child session but rotates the V1 run UUID so native terminal tombstones are respected. Background concurrency is capped at 4 with cancellation-safe queueing and atomic preset startup. Product guide: `docs/usage/subagents-v2.md`. Model-driven end-to-end acceptance remains pending. |
| Workflow (Rhai / `/workflow`) | Upstream engine + Pi spawn seam | **Session host + slash surface:** reuses `xai-workflow` + `ExternalWorkflowRuntime`; adapter `x.ai/workflow/{launch,pause,stop}` + `x.ai/workflows/list` + `workflow_updated`; injects `/workflow`, `/workflows`, `/create-workflow` (+ named scripts); hides `__pi_workflow_*` bridge cmds; Pager local handlers + F2 gate. `/create-workflow` is Pager PassThrough user prompt (not a Pi skill). Project scripts default to `<repo>/.grok-pi/workflows`. Live deep-research handtest still recommended. |
| Prompt completion | Adapted | Pi `agent_settled` remains the normal completion barrier. Adapter-promoted client rows keep their ACP waiter; extension/Pi-owned runs emit `x.ai/session/prompt_complete`. An idle probe closes prompts consumed by input handlers without `agent_start`/`agent_settled`, preventing ghost “Waiting…” state. |
| Retry | Adapted | Grok native sticky status/toast |
| RPC connection resilience | Adapted | Unexpected Pi RPC child exit triggers automatic respawn with backoff (storm guard: max 3 recoveries per 5 min), fresh bootstrap, and `switch_session` reattach of the pre-crash session file; deliberate teardowns (probes, respawn) carry `intentional` and are skipped. A `get_state` heartbeat watchdog (15 s cadence; 4 consecutive deadline misses ≈ 2 min unresponsive) kills a live-but-wedged child into the same recovery path (`PI_GROK_RPC_WATCHDOG=0` disables). In-flight prompts/queue rows are cancelled, not replayed. |
| Compaction | Native+Adapted | `/compact [instructions]` → Pi `compact`; Pi `compaction_*` → native CompactionStarted/Completed/Failed/Cancelled scrollback blocks + sticky status. Successful full summaries are projected live and on replay as a native foldable Markdown `SessionEventBlock`, collapsed by default. |
| Session recap (`/recap` + auto away) | Adapted | initialize `meta.sessionRecap`; `x.ai/recap` → inject extension `__pi_grok_recap` (called on `complete` side, appends a non-context custom entry via `appendEntry`, so summaries never enter the agent loop context; legacy sendMessage-era custom messages are stripped from LLM context by the extension's `context` hook) → custom entry `pi-grok-recap/v1` (`entry_appended`) → `SessionRecap`. Uses only the `recap_model` explicitly configured via F2, never falls back to the current session model; auto: ≥3 turns, last completed turn ≥3 minutes old, generated in background while terminal unfocused, not repeated if no new turn after success; manual: any user turn qualifies; optional `/recap [focus]` / `/summarize [focus]` injects `customInstructions` into the recap prompt (append, same pattern as `/compact`); input limited to last 6 turns/12k chars; body language prefers macOS `AppleLanguages`, then …
| BTW history (`/btw` + `/btw-history`) | Adapted | Live deltas/answers stream through `appendEntry("pi-grok-btw/v1", …)` custom entries — never `sendMessage`, so bridge traffic never enters the agent loop context (legacy sendMessage-era custom messages are stripped from LLM context by the extension's `context` hook). Successful answers are also written with `appendEntry("pi-grok-btw/history/v1", …)` as non-context custom entities containing the question, answer, timestamp, request id, and used model. Adapter rebuilds the active branch from `get_entries` on load/tree switch and projects records onto native `BtwBlock` scrollback; the dynamically advertised `/btw-history` command refreshes and displays the same records without invoking a model. |
| Queue pane / count | Adapted+Boundary | Adapter-owned client/extension rows — including mid-turn steer rows — support real remove, clear, edit, reorder, and interject operations before dispatch, so a queued steer is cancellable until its safe-point forward. Stable ids and versions preserve Pager reconciliation and original display text. Pi `queue_update` still feeds a read-only external lane for messages that bypass interception; only follow-up dequeue advances `runningPromptId`, while steering remains in the current turn. Queue drain mode remains settable via `pi/queue/mode` (`one-at-a-time` / `all`). |
| Context bar used tokens | Adapted | Pi `contextUsage` / message usage → ACP `_meta.totalTokens` → top-right bar |
| Context click / `/context` | Native+Adapted | Grok `x.ai/session/info` → Pi stats + messages + `__pi_context_breakdown` + optional `cacheMetrics` (from `get_entries`, pi-cache-graph formula) → native `ModalWindow` (`ContextInfoBlock` + views `0/1/2/3/s`, `e` export, `r` refresh); F2 `[ui].pi_cache_graph` default on; live refresh while running, not written to scrollback |
| User prompt markdown (grok-pi) | Native | F2 `[ui].pi_user_markdown` default on; collapsed/truncated prompts keep the native 3-line `UserPromptBlock` preview, while expanding renders the body with agent Markdown and preserves user chrome. Toggling the setting keeps the current fold state; off uses the classic plain-text renderer throughout. |

## Slash Commands

### Retained Grok Native Commands

`exit`, `help`, `hotkeys` (aliases `shortcuts`/`keys`), `tutorial` (aliases `tour`/`onboarding`), `new`, `compact`, `model`, `effort`, `rename`, `resume`, `session-info` (alias `session`), `tree`, `tree-map`, `fork`, `clone`, `reload`, `notify`, `dashboard`, `recap`, `btw`, `copy`, `find`, `jump`, `review-session`, `review-message`, `transcript`, `export`, `expand`, `queue`, `multiline`, `compact-mode`, `vim-mode`, `theme`, `timestamps`, `timeline`, `toggle-mouse-reporting`, `voice`, `doctor`, `debug`, `pi-config`, `pi-models`, `pi-shortcut-manager`. Individual visibility/capability gates still apply. When F2 `pi_btw` is enabled, the Pi extension also advertises `/btw-history` as a direct, model-free history view.

### Dynamic Pi Commands

Extension, Prompt Template, and Skill commands returned by Pi are not hard-coded in Rust. They enter the Grok native slash suggestion/dropdown through the ACP command catalog; name conflicts are de-duplicated by the Grok registry. Built-in bridge extensions can also add Pi-provider auth (`/login`, `/logout`), Pi HTML export/share (`/export-html`, `/pi-share`) and F2-gated workflow/automation commands.

### Deliberately Excluded

Stock Grok product or local session-store commands—including Grok `/history`, Grok account `/login`/`/logout`, `usage`, `plugins`, `mcp`, `memory`, `workspace`, and `share`—are excluded. The same bare `/login`/`/logout` names may be supplied by grok-pi's Pi auth extension, where they authenticate Pi model providers rather than Grok.com. The original `/minimal` and `/fullscreen` re-exec commands are also not exposed: switch screen mode at startup so Pi process arguments are preserved.
