# PR: Bash 项目级/Session 级 env 工具与 .env 加载

## 背景与目的 (Why)

Pi 每次 Bash 调用都 spawn 新的 `/bin/bash -c`（Windows 为 `bash -c`），命令内 `export` 无法跨调用保留。需要让 Agent 自主管理可跨 Bash 调用、可随 `/resume` 恢复的环境变量，同时只读加载项目已有的 `.env`。

范围经多轮澄清定稿：一个 tool、两层覆盖、`.env` 用 `ENV_<KEY>` 暴露、spawn env 合并（不改命令文本）、不引入第三方库。

## 变更内容概述 (What)

- 新增 `bash_env_tool`：单 tool 支持 `action: set|delete|list`、`scope: project|session`（默认 session）。
- 三层来源合并进增强 Bash 的前台/后台 spawn env：`Pi base < <cwd>/.env < <cwd>/.pi/env.json (project) < session`。
- `.env` 只读，用 Node 内置 `util.parseEnv` 解析 `k=v`，键统一暴露为 `ENV_<KEY>`（已有 `ENV_` 前缀保持不变）；不引入 npm 依赖、不转写第三方源码。
- project 层由 Agent 读写 `.pi/env.json`，文件加入 `.gitignore` 并设为 0600。
- session 层用 `pi.appendEntry("pi-grok-session-env/v1", { set, delete })` 持久化（不进入 LLM context），按 leaf id 变化从 `getBranch()` 重放，覆盖 `/resume`、新建会话与 `navigateTree`。
- 保留键校验（`PI_*`/`GROK_*` 前缀与 `PATH/HOME/SHELL/...`）、键名格式校验、NUL 值拒绝；`list`/`set` 结果不回显值。
- `PI_GROK_BASH=0` 时不注册 `bash_env_tool`。
- 工具名与提示词定稿：`bash_env_tool`；description 说明两层生命周期与合并顺序，snippet 只答「何时调用」，3 条 guidelines 覆盖 `.env → $ENV_<KEY>`、恢复/覆盖语义、保留键与明文风险；`prompts.ts#buildBashPrompts` 增加一条 Bash guideline 联动。校验仍在 `execute`，提示词不承担安全约束。

## 风险与影响评估 (Risk Assessment)

- 值以明文落在 `.pi/env.json`、`.env` 与 session JSONL；不应用于长期密钥。`.pi/env.json` 已 gitignore，`.env` 原本已忽略。
- 多个 grok-pi 进程并发写同一 `.pi/env.json` 可能丢更新（本轮无文件锁）。
- 仅增强 Bash 生效；Eval、原生 Pi Bash、子代理不注入。运行中任务持有 env 快照，后续变更不影响。
- 成本三轴：
  - **UX**：一次设置、后续 Bash 持续生效；项目级本地共享、session 级可随 `/resume` 恢复；代价是值明文落盘且工具结果不回显值。
  - **DX**：新增 1 个 TS 模块 + 1 个回归文件 + injector 1 处物化；复用现有 bundle，避免新增扩展接线。
  - **Agent-legibility**：单一 tool 契约、固定 customType、按 active branch 顺序重放；无 side channel、无 monkey-patch，行为由回归固定。

## 回滚方案 (Rollback Plan)

1. 立即停用（无需改代码）：`PI_GROK_BASH=0 grok-pi` 或 F2 `[ui].pi_bash=false`，`bash_env_tool` 与增强 Bash 都不注册。
2. 完全回退：还原本次 7 个修改文件，删除新增的 `env-tool.ts`、`test-env-tool.mjs`；删除本地 `<cwd>/.pi/env.json` 与 `.gitignore` 中对应条目。
3. session custom entries 为 `type=custom` 的 `pi-grok-session-env/v1`；旧版本 Pi 会忽略它们，不破坏现有会话树或 `/resume`。
4. `.env` 只读，本次变更不写该文件；`.pi/env.json` 未入库，直接删除即清除项目级状态。
