# Issue: 大文本粘贴选择与临时文件引用

## Goal

当用户粘贴至少 100 行文本时，在不改变默认粘贴语义的前提下提供“正常粘贴”或“保存为临时文件并插入引用”两种选择。

## 背景/问题

超长日志、代码和 JSON 直接进入 prompt 会显著占用输入区域，并让用户难以决定是否应改为文件引用。现有粘贴链路还包含图片/文件探测，因此新行为必须位于既有分类逻辑之后，不能破坏图片粘贴、Finder 文件路径和普通文本粘贴。

## 验收标准 (Acceptance Criteria)

- [x] WHEN 粘贴文本达到 100 行，系统 SHALL 打开两项选择器；99 行及以下不触发。
- [x] WHERE 选择器打开，第一项 SHALL 为 “Paste normally”，保持当前行为为默认选择。
- [x] WHEN 选择 “Paste normally” 或关闭选择器，系统 SHALL 按原粘贴路径插入原始文本。
- [x] WHEN 选择 “Save as temporary file”，系统 SHALL 以不覆盖既有文件的方式写入会话临时目录，并向 prompt 插入文件路径引用。
- [x] WHERE 插入文件引用，系统 SHALL 总是附带字节数和行数；仅在内容可解析为 JSON 时附带 `json=true` 提示。
- [x] IF 临时文件写入失败，THEN 系统 SHALL 提示失败并回退到正常粘贴，避免数据丢失。
- [x] WHERE Cmd/Ctrl+V 与 bracketed `Event::Paste` 两条主入口，系统 SHALL 共享同一大文本阈值和选择逻辑。
- [x] WHERE 既有图片/文件探测已认领粘贴，系统 SHALL 不抢占该流程。

## 关键决策

| 决策 | 理由 |
|------|------|
| 仅以 100 行作为触发阈值 | 需求边界明确，避免把单行大文本误判为“超长粘贴”。 |
| 复用 ArgPicker | 已有键盘/鼠标/搜索/关闭语义，新增专用 modal 属于不必要复杂度。 |
| 第一项保持正常粘贴 | 默认行为不变，降低行为惊讶。 |
| 使用 `create_new(true)` 递增文件名 | 防止覆盖已有 paste 文件。 |
| 写文件失败回退正常粘贴 | 保护用户数据，避免选择失败后内容丢失。 |
