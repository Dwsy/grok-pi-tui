# Issue: 修复 Pi 0.84.3 bundled CLI 扩展私有模块解析

## Goal

让 grok-pi 及现有第三方扩展在 Pi 0.84.3 的 `dist/bundle/cli.js` 入口下正确解析 Pi 模块，并将 grok-pi 的最低兼容版本提升到 0.84.3。

## 背景/问题

Pi 0.84.3 将系统 CLI 入口切换到 `dist/bundle/cli.js`，但 grok-pi 与第三方扩展仍把 `dirname(process.argv[1])` 当作 `dist/`。因此私有模块被错误解析为 `dist/bundle/<module>`，触发扩展加载失败和 grok-pi 自愈重启。

## 验收标准 (Acceptance Criteria)

- [x] `pi` 0.84.3 通过 RPC 启动 `pi-model-selector-x`、`pi-treex`、`resume-x` 时无模块加载错误。
- [x] grok-pi 注入的 rpc-compat、export、auth、Remote TUI、native commands 和 shortcut 相关模块在 bundled CLI 下解析到 `dist/`。
- [x] grok-pi 启动检查与 README、脚本、Feature Matrix 的最低 Pi 版本一致为 0.84.3。
- [x] 相关 Rust 注入器测试、Pi 扩展加载复现和 diff 范围审查通过。

## 关键决策

| 决策 | 理由 |
|------|------|
| 从 bundled CLI 入口目录回退到父级 `dist/`，传统 `dist/cli.js` 保持原路径 | 同时覆盖 Pi 0.84.3 默认入口与 `--pi-bin` 指向模块化 CLI 的开发/测试入口。 |
| 只修复实际生产和用户启用的 hostUrl 解析点，不修改 Pi 源码或扩展功能语义 | 故障是入口路径回归，扩大范围会破坏既有 RPC/TUI 边界。 |
