# Issue: 子代理无污染实时传输与恢复

## Problem

`pi-grok-subagent/v1` 已从单一 Pi RPC custom-message 流迁移到本地 socket，但 lifecycle 仍通过 `appendEntry` 复制到父 Pi session，状态快照仍以 `pi-grok-subagent-state/v1` 写入父 JSONL。socket 与 RPC 两个独立接收通道会乱序；较新的 `finished` RPC 副本可推进 adapter 高水位并丢弃较早的 child prompt/text/tool delta，留下只有 `Worked for` 的空 child `AgentView`。

## Complexity

L3：跨 V1/V2 共用 runtime、实时 bridge、恢复索引和 adapter 投影。

## Contract

- UI-only `spawned/child_update/finished` 共用一个进程私有 ordered socket，不进入父 session JSONL。
- 子代理索引写入父 session 文件旁的独立 `<parent>.subagents.jsonl` sidecar。
- child transcript 继续由 Pi child `SessionManager` 写入独立 child JSONL。
- 父 session 的正常 `spawn_subagent` tool call/result和 V2 模型可见语义消息仍属于真实对话语义，不视为 UI bridge 污染。
- `/resume` / session switch 在 `session/load` barrier 内显式触发 sidecar lifecycle + child JSONL replay，不从 extension `session_start` 提前发送。

## Acceptance Criteria

- [x] V1 background/foreground child 均在运行期间显示顶部 row，fullscreen 实时显示 prompt/text/thinking/tool history。
- [x] child finished 后 Waiting 正确落到 Completed/Failed/Cancelled，最后一批 delta 与工具结果不丢失。
- [x] fullscreen `Esc`/`q` 只关闭 takeover；Ctrl+C/Stop 才取消 child，快捷提示与行为一致。
- [x] `/resume` 在 root `session/load` barrier 内完成 spawned → bounded transcript → finished，并等待 socket replay-complete marker。
- [x] Eval v2 `agent()` 与 V2 `spawn_team` / `spawn_team_agent` 共用同一 runtime/ordered socket；V2 reactivation 使用唯一 Pager run identity 和 leaf 边界。
- [x] RPC crash recovery 只终止 running orphan，不重复已渲染 transcript，不留下 Waiting/Cancelling。
- [x] 新运行的父 JSONL 不含 `pi-grok-subagent/v1` 或 `pi-grok-subagent-state/v1`；sidecar 尾部损坏可容忍。
- [x] socket 缺失、连接失败或超时在 child 启动前 fail fast，不静默创建空 child view。
- [x] extension、injector、adapter、Pager production check/build 与真实 TUI handtest 全部有证据；Pager lib-test target 另受仓库既有无关 fixture/API 基线错误阻断。

## Rollback

恢复 lifecycle/state `appendEntry` 写入并移除 sidecar；无需修改 child session 文件。
