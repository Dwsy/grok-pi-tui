# 后台 Bash 完成信息通过 Pi 会话边界注入模型上下文

- 日期：2026-10-30
- 状态：已实现（待完整端到端 UI 验证）
- 范围：`extensions/pi-grok-bash/{bash-tasks.ts,index.ts,test-v2.1.mjs,README.md}`

## 背景

Pi 会话里完成很久的 Bash 任务可能在后续多个回合才以独立 follow-up 通知再次唤醒模型。
Pager 的 `__pi_grok_bash_task__` 带外任务状态已经能及时更新，但模型通知仍使用
`pi.sendMessage(..., {triggerTurn:true, deliverAs:"followUp"})`，两者必须分开治理。

## Pi 源码核对

- `pi.appendEntry(customType,data)` → `SessionManager.appendCustomEntry`，仅持久化扩展状态，**不进入 LLM 上下文**。
- `custom_message` session entry → `SessionManager.buildSessionContext()`，**会进入 LLM 上下文**。
- `turn_end` 和 `agent_before_settle` 的 `BoundaryResult.entries` 可附加 `custom_message` 草稿，并用 `continue:true` 请求继续生成，不必进入 steer/follow-up 队列。
- Pi 已经发出的 provider 请求不能被异步修改；完成信息最早在下一次 provider 调用前可见。

## 实现

1. Bash 子进程结束时继续先推送 `ui.setStatus` 完成状态，保障 Pager 及时收敛。
2. Agent 正在运行：暂存完成消息，在最近的 `turn_end` 或 `agent_before_settle` 使用 `custom_message` 边界草稿批量追加；正常结束时 `continue:true`，取消时只追加、不自动继续。
3. Agent 空闲：直接 `pi.sendMessage(...,{triggerTurn:true})`；在最后边界之后、`agent_settled` 之前完成的任务有兜底投递。
4. 显式 kill 不向模型重复注入消息；UI 终态仍由带外通道发送。

## 验证

- `node extensions/pi-grok-bash/test-v2.1.mjs`：PASS（成功/失败、多个完成消息、abort、不重复投递、settled 兜底）。
- 完整 Pi RPC → Adapter → Pager 实际运行的延迟测量仍需端到端确认。
