# 插件 dev 模式：从文件夹加载内置扩展

开发内置 Pi 扩展时，改一行 TS 就要重新 `cargo build`（源码用 `include_str!` 烘进二进制）。
本变更让宿主在启动时改从磁盘目录加载同名扩展。

## 背景与目的 (Why)

- 内置扩展的源码是 `extensions/<name>/index.ts`，Rust 注入器用 `include_str!` 编译期内嵌，启动时写进 `$TMPDIR/pi-grok-<name>-XXXXXX/` 再以 `--extension` 交给 Pi。
- 结果是每次改插件都必须重新编译 grok-pi，前端/插件迭代成本高。
- 需要一种显式、可选择的方式，用「全部插件的父级文件夹」替换内嵌副本。

## 变更内容概述 (What)

| 文件 | 变更类型 | 描述 |
|------|---------|------|
| `crates/codegen/xai-grok-pager-bin/src/bin/grok_pi/ext_dev.rs` | 新增 | `ExtensionDev`：解析/校验 dev 根目录，提供 `<root>/<name>/index.ts` 与路径替换 |
| `crates/codegen/xai-grok-pager-bin/src/bin/grok_pi/cli.rs` | 修改 | 新增 `--extensions-dev <DIR>` 与 `--help` 说明 |
| `crates/codegen/xai-grok-pager-bin/src/bin/grok-pi.rs` | 修改 | 启动解析 dev 根；两处 `--extension` 装配表带扩展目录名；子代理扩展目录同步改写 |
| `README.md` / `docs/README.zh-CN.md` | 修改 | 记录开关用法与失败语义 |

### 1. 入口与解析

`ExtensionDev::from_arg(args.extensions_dev.as_deref())`：先用 `--extensions-dev`，再退回 `PI_GROK_EXTENSIONS_DEV`。
`canonicalize()` 失败或不是目录 → 启动失败（不静默回退内嵌副本）。
仅在 `--no-bridge-extensions` 未开启时解析：该开关关闭时没有任何内置扩展会加载，dev 模式无意义。

### 2. 只替换「源文件来源」，不替换功能门控

`ext_dev::source_path(dev, folder, embedded)`：dev 模式开启时返回 `<root>/<folder>/index.ts`，否则原样返回内嵌路径。

- 保留全部既有语义：`--no-bridge-extensions`、F2 开关、`HostFeatureManifest::resolve_enabled`、环境开关、加载顺序。
- 注入器仍然执行（控制文件、socket、`grok-pi.json` UI 清单、skills 缓存等副作用不变），只把交给 Pi 的入口路径换成磁盘文件。
- `builtin:codemode` 是 Pi 资源 id，没有对应目录，`folder = None` 时原样透传。
- 用户 `-e` 路径、`launch_plan.extensions`（第三方 Pi 扩展）不受影响，也仍走资源准入策略。

### 3. 子代理扩展目录同步

`PI_GROK_SUBAGENT_EXTENSION_CATALOG` 里的路径与 `--extension` 同源。装配时记录 `(内嵌路径, dev 路径)`，装配完成后改写目录条目，避免子代理回落到内嵌副本。

### 4. 失败语义

- 根目录不存在 / 不是目录 → 启动失败并给出路径。
- 已启用扩展在 dev 目录缺 `index.ts` → 启动失败并提示需要 `＜parent＞/＜extension＞/index.ts` 布局。
- `tracing::warn!` 记录 dev 根，避免误用后无从察觉。

## 风险与影响评估 (Risk Assessment)

- 默认路径零改动：不传开关时 `source_path` 原样返回内嵌路径。
- 装配表新增目录名常量，与 `extensions/` 实际目录一一对应；目录名写错会在 dev 模式下启动即报错，而不是静默加载旧副本。
- `navigate_tree` 桥接是 Rust 内联 TS（无 `extensions/` 目录），因此不可 dev 覆盖，行为不变。
- 已知边界：dev 模式只替换扩展**入口源码**。宿主另行 materialize 的资产（`web_config` 的 `web/*.html|css|js` 副本、`grok-pi-config` SKILL 缓存）仍来自二进制，改动需重新编译。

## 回滚方案 (Rollback Plan)

- 不传 `--extensions-dev` / `PI_GROK_EXTENSIONS_DEV` 即回到内嵌副本。
- 代码回滚：还原 `grok-pi.rs`、`cli.rs` 改动并删除 `ext_dev.rs`（无数据结构或配置格式变更）。

## 测试命令

```bash
./scripts/cargo-shared.sh test -p xai-grok-pager-bin --bin grok-pi
./scripts/cargo-shared.sh check -p xai-grok-pager-bin --bin grok-pi
```

手动验收：

```bash
grok-pi --extensions-dev ./extensions            # 改动 extensions/*.ts 后只需重启
PI_GROK_EXTENSIONS_DEV=./extensions grok-pi      # 等价的环境变量形式
```
