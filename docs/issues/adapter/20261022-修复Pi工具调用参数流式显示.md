# 修复 Pi 工具调用参数流式显示

## Goal

Pi 模型开始生成工具调用时立即在原生 Grok Pager 显示工具卡，并在参数 JSON 持续生成时更新 `raw_input`；工具开始执行后仍复用同一个工具调用 ID 与既有生命周期，不改变工具执行语义。

## Root cause (verified from source)

Pi RPC's `toJsonEvent` intentionally removes the cumulative `partial` assistant snapshot from `message_update`. For `toolcall_start`, it retains `contentIndex`, `id`, and `toolName`; for `toolcall_delta`, it retains `contentIndex` and the raw JSON `delta`; `toolcall_end` carries the canonical `toolCall`. The adapter currently ignores these three event kinds, so the first ACP tool card arrives only with `tool_execution_start`, after argument generation has completed.

## Acceptance criteria

- [x] `toolcall_start` publishes an in-progress ACP tool card for streamed tools; Execute/Bash waits for canonical execution start (2026-10-30 policy).
- [x] Interleaved `toolcall_delta` events are accumulated by `contentIndex`, parsed best-effort, and update the same ACP card's `raw_input` without waiting for the full JSON object.
- [x] `toolcall_end` publishes the final authoritative arguments; subsequent `tool_execution_start/update/end` events keep using the same ID and existing behavior.
- [x] Hidden Eval-v2-only calls remain hidden; text/thinking streaming and existing tool output rendering are unchanged.
- [x] Regression tests cover partial string/object arguments, malformed/incomplete suffixes, interleaved content indexes, and final-argument replacement where practical.

## Implementation plan

1. Add a dependency-free partial JSON object parser in the adapter model layer; prefer complete values and salvage the last complete top-level fields when the current suffix is incomplete.
2. Track streamed tool calls by Pi `contentIndex` in adapter state, emitting ACP `ToolCall` at start and `ToolCallUpdate.raw_input` as arguments grow.
3. Reconcile with canonical arguments at `toolcall_end`; clear stale stream state at message/turn boundaries.
4. Add regression tests, run adapter tests and the focused `grok-pi` check, and review the final diff.

## 2026-11-02 follow-up: preview cards must honor `collapsed_edit_blocks`

Report: with `[ui].collapsed_edit_blocks = true` (and `respect_manual_folds = true`), freshly streamed `edit`/`write` cards still auto-expanded.

Root cause:
- `toolcall_start` pushes the Edit card with empty `raw_input` and no content, so `path_from_title` fired and marked `summary_untrusted`; `edit_default_display_mode` treats an untrusted summary as an expand escape, bypassing the collapse override at push time.
- `replace_tool_block` only handled the trusted→untrusted rising edge. When the canonical call later supplied `file_path` (untrusted→trusted), nothing re-ran the materialize policy, so the preview-time expand stuck for the card's lifetime.

Fix:
- `tool_call_to_block`: `path_from_title` now marks the summary untrusted only when diffs already exist (`(path_from_title && diff_count > 0) || diff_count > 1`). An empty preview has no one-liner to distrust; a title-fallback with real diffs and multi-file patches keep the escape.
- `replace_tool_block`: added the untrusted→trusted falling edge — re-runs `edit_default_display_mode` when the entry is Expanded and not pinned, so a trustworthy canonical summary re-applies the user's collapse default. Pinned folds/expands (`respect_manual_folds`) are never re-materialized.
