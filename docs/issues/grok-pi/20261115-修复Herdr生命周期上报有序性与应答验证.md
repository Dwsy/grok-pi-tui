# grok-pi Herdr 生命周期 Header 接管

## 目标与约束

仅调整内置 Pi Extension，避免重复状态机、额外轮询、Herdr 源码修改或强制修改进程标题。Herdr Header 的 authority 是最终验收条件，而不仅是 socket 收到数据。

## 诊断

- 既有 grok-pi pane 的 session ref 已到 Herdr，但 `screen_detection_skipped=false`，Header 仍使用 fallback。
- 该 pane 的前台进程组中已存在 `argv0=pi` 的 Node 子进程；旧报告的 `pi-rpc` 进程标题根因不成立。
- 原内置扩展把任意 socket 返回视为成功，并在 `agent_start` 并发发送 session、state。
- Herdr 的应用层成功回复只说明 API 处理完成，不承诺状态已经获得 authority。

## 已实现

- [x] 单 FIFO 保证 session 在 state 之前；每个报告在入队时快照 session ref 和 seq
- [x] JSON 响应校验、有限重试、去重诊断写入 Pi RPC stderr
- [x] 仅合并连续未发送状态，保留 session 切换边界；切会话时清掉 blocker
- [x] Node socket 4/4 测试通过（含延迟应答、错误响应及拆包）
- [x] 保持 Herdr / Pi / Rust host 的原有接口不变
