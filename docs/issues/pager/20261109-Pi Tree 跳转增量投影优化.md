# Issue: Pi Tree 跳转增量投影优化

## Goal

在保证 Pi 分支语义和完整回放结果一致的前提下，让 grok-pi 的 `/tree` 跳转复用共同历史，仅更新发生变化的 Pager 滚动历史，降低长会话切换成本。

## 背景/问题

当前 `/tree` 调用官方扩展桥接 `ctx.navigateTree` 切换同一 Pi session 的 leaf。导航成功后，Pager 的 `handle_session_tree_navigated` 重置 tracker、Todo 与整个 `ScrollbackState`，创建占位项并执行 `session/load`；adapter 的 `replay_history` 再逐项投影目标活动分支。因而即使两条分支大部分相同，显示历史也会重建。

已有 `get_entries(since)` append-log 缓存减少 Pi RPC 数据传输，并按 leaf 回溯 parent chain；它不消除 Pager 的完整分支重放。终端可能已有帧差分：**尚未测量终端输出量、耗时或内存，不能将对象重建直接等同于终端全屏重绘**。

源码依据：

- `crates/codegen/xai-grok-pager/src/app/dispatch/session/tree.rs`：导航结果清空状态并发起 `Effect::LoadSession`。
- `crates/codegen/pi-grok-adapter/src/pi_adapter/session.rs`：导航后刷新 entry 缓存。
- `crates/codegen/pi-grok-adapter/src/pi_adapter/replay.rs`、`agent.rs`：`session/load` 重放活动分支及 subagent 等状态。
- `crates/codegen/pi-grok-adapter/src/model.rs`：`PiReplayEntry` 当前保留内容和时间戳，不携带来源 entry ID；缓存保存 parent chain。
- `crates/codegen/xai-grok-pager/src/scrollback/state/mod.rs`：已有 `remove_from`，但截断后仍需核对 tracker、索引和布局等状态。

## 范围和约束

- 首期限定 **同一 Pi session 内** 的 tree 跳转，包括 `/tree` 与复用同一导航路径的入口；不改变 `/resume`、`/fork`、`/clone` 的独立生命周期。
- Pi 继续拥有 session、leaf 与导航；使用现有官方 extension bridge，不修改 Pi 源码、不直接编辑 JSONL、不以 fork 代替导航。Grok Pager 保持唯一终端 UI，adapter 保持 headless。
- 分支共同前缀比较必须使用稳定 session entry 身份，而非文本、时间戳或滚动条目数量。一个 entry 可能产生多个显示块，tool start/result 或聚合消息可能跨边界。
- 未证明状态可安全复用时走现有完整 `session/load`。摘要、compaction、特殊 custom entry、旧 host 和失败等情况先保守回退，只有经测试证明等价后才扩大覆盖。

## 候选设计

1. 在 adapter 缓存中取得导航前后的活动 parent chain，验证 session/leaf 和链完整性，计算共同前缀及目标后缀；保留 entry 身份到 replay projection 的关系，明确一对多、无显示条目与跨 entry 工具卡片的安全边界。不得把选择的 entry ID 假设为最终 leaf：导航可能生成摘要或改变实际 leaf。
2. 在 Pager 为**完整回放和实时投影**建立同一套 session entry → 显示块/安全截断点映射。先验证消息合并、工具结果、流结束以及非持久化本地块是否可准确归属；不能证明时禁止增量路径。
3. 导航成功并校验基线后，在批处理内复用共同前缀、移除旧后缀、投影新后缀；保留未受影响块的身份及可复用布局。检查选择、滚动锚点、展开状态、索引和 tracker，并避免移除与分支无关但需保留的 UI 状态。
4. 审计 Todo、workflow/revision、compaction、BTW、subagent、模型与上下文等旁路状态，逐项确定基于目标分支重算、独立同步或触发完整回放。不可只更新可见文本后宣称一致。
5. 应用过程使用 session ID、旧 leaf/版本和请求代次校验；乱序、失效、取消、数据缺失或应用失败时停止增量并使用完整回放恢复。关注导航已成功但 UI 投影失败的事务边界，避免旧 UI 被错误标记为新 leaf；重复切换与迟到事件不得混入当前分支。
6. 保留现有完整回放作为对照和兼容回退；避免重复 RPC 和额外重放，但只有在保证刷新与事件顺序正确时才移除。具体协议和边界以 Phase 1 的代码审计、实测结果确定。

## 验收标准

- [ ] 同 session 从当前 leaf 跳到祖先、后代或兄弟分支后，展示及状态与同一目标 leaf 的完整回放一致；不混入旧分支尾部。
- [ ] 安全增量场景保留共同前缀显示块身份，不重复构造/重放该前缀；无差异跳转不会不必要地重建历史。
- [ ] 用户消息、assistant 文本/思考、图片、工具开始与结果、错误、compaction、摘要和 custom entries 不丢失、不重复，顺序正确。
- [ ] Todo、workflow、BTW、subagent 及其他旁路状态经审计并与完整回放一致；未能证明安全的情况明确回退。
- [ ] 缓存缺失、旧 host、损坏或缺失 parent、未知来源、过期结果、切换失败及增量应用失败时安全回退，不串 session/leaf；Pi 的 editor text 和原有导航行为保持正确。

## 关键决策

| 决策 | 理由 |
|------|------|
| 优先复用共同分支的投影 | 既有日志增量缓存无法避免 Pager 全量重放，需覆盖投影成本。 |
| 用来源 entry ID 与安全截断边界 | 文本可能重复，一个 entry 可能对应多个块，工具状态可能跨 entry。 |
| 不确定时完整回放 | 保持 Pi 和 Pager 状态一致性优先，逐步扩大经过验证的安全场景。 |
| 以完整回放和实测为对照 | 同时验证语义正确和实际性能收益，区分终端帧差分与应用层重建。 |
