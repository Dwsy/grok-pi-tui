## 阶段 1：移除 Pi 编译过程中未使用的 jemalloc

`xai-grok-pager-bin/src/main.rs` 是唯一为 stock Grok 安装 `#[global_allocator]` 的入口，`src/bin/grok-pi.rs` 不安装 jemalloc。此前共用包默认特性使 Pi 多编译 `tikv-jemalloc-sys`（上次 ARM64 该单元持续 173.7 秒）。

- Pi 的本地构建、发布构建与缓存预热使用 `--no-default-features`，但仍明确启用 `sandbox-enforce`。
- stock Grok 的包默认特性及全局分配器不变。
- CI 通过 `cargo tree -e normal,build` 断言三项 jemalloc 依赖均不可达，并编译真正的 ARM64 release 二进制；检查 `--version`、`--help` 与 `--print-capabilities`。
- **状态**：第一刀在修复基线 Pager 配置初始化问题后，由 [CI #43792742800](https://github.com/Dwsy/grok-pi-tui/actions/runs/43792742800) 完整通过；不得将观测到的 wall-clock 差直接全部归因于 jemalloc。

### 第一轮 CI 失败与修复

- CI Run [43787682227](https://github.com/Dwsy/grok-pi-tui/actions/runs/43787682227)：jemalloc 依赖断言通过，`release-dist` 编译失败（`E0063`）。
- 编译失败来自基线 Pager 的 `PagerLocalSnapshot` 新增 `ask_user_question_timeout_secs` 后，5 处初始化器和启动期 App 配置镜像未同步，并非 jemalloc 裁剪引起。
- 修复将有效 TOML 中的正整数超时读取为 `Option<u64>`，在 App 中缓存，并传递到 dashboard、prompt、settings 的 5 个初始化器；无有效配置时交由 Snapshot 使用默认值，避免在热路径反复读取磁盘。
- 历史状态：当时先修复，再运行第二次 ARM64 CI。之后用户授权更大批量地继续拆分，取消逐刀 CI 门槛。

## 阶段 2：从 Pi 编译依赖中解耦 stock Grok 的 cryptify

- 阶段 1 修复提交 `f1b14cd4` 的 [ARM64 CI #43792742800](https://github.com/Dwsy/grok-pi-tui/actions/runs/43792742800) 已完成并成功：jemalloc 依赖检查、release-dist 编译、三个 CLI smoke tests 均通过；本轮 Build elapsed 2848 秒。相较历史基线 3013.8 秒，差 165.8 秒，但缓存状态与环境不同，不能归因于 jemalloc。
- 静态依赖审计确认 `cryptify` 在整个工作区仅被 stock `xai-grok-pager-bin/src/main.rs` 使用一次，Pi 入口完全不使用。将其改为可选的 `stock-obfuscation` feature（stock 默认与 default-bazel 均开启）；无该 feature 时 stock 入口使用语义等价的普通赋值，确保 `--no-default-features` 仍可编译。
- Pi 的 release-dist + sandbox-enforce feature 集不启用 `stock-obfuscation`，因此 Cargo 不应构建 `cryptify`。CI 依赖树断言同时检查 jemalloc 与 cryptify；保留所有 Pi RPC、ACP、原生 Pager、Herdr、Dashboard、Remote TUI 和 sandbox-enforce。
- **验证状态**：[CI #43798146593](https://github.com/Dwsy/grok-pi-tui/actions/runs/43798146593) 已完成成功。后续批量改动无需逐刀重复该 CI。
