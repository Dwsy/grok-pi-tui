# Issue: grok-pi 产品依赖断连分析

## Conclusion

当前 `grok-pi` 不是只编译“Pager UI + Pi adapter”。`xai-grok-pager` 与 `xai-grok-shell` 都是无编译期 profile 的单体库；External profile 只在运行时隐藏 stock Grok 功能，因此 MCP、插件市场、产品遥测、stock agent runtime、workspace/computer-hub 和完整 Grok tools 实现仍进入构建图。

`cargo metadata` 显示 `xai-grok-pager-bin` 当前可达 **1296 个唯一 package**。下述 package 数是“若所有入边都被 feature-gate 后可从 root graph 消失”的静态上限，不等于线性编译时间收益。

## Findings

| 候选 | grok-pi 运行需求 | 静态可消失 package | 判断 |
|---|---:|---:|---|
| `xai-grok-mcp` | 不需要；Pi 自己拥有 MCP，adapter 无 MCP 运行调用 | 9 | 高置信可断连，需跨 config-types/shell/workspace/pager feature |
| `xai-grok-plugin-marketplace` | 不需要；Pi 使用自己的 extension/package/resource 系统 | 1 | 可断连；package 数收益小，但可减少约 14.4k 行 stock plugin/CTA 编译面 |
| `xai-grok-telemetry` heavy engine | grok-pi 只需要日志/少量 startup API，不需要 Mixpanel/Sentry/product OTEL engine | 33 | 应改成轻量 facade/no-op profile，不能直接删 crate API |
| `xai-grok-tools` implementations | Pager 需要 UI DTO/输出类型，不需要完整 Grok tool runtime | 71 | 最大隐藏收益；拆 leaf UI/types crate，不可整 crate 直接删除 |
| `xai-grok-shell` stock runtime | adapter 仅用 config/workflow/persistence；composition 仅用 config/host_features | 50 | 高收益但高耦合，需要提取 leaf contracts 后断连 |
| `xai-grok-workspace`/Computer Hub | 大部分 stock workspace runtime 不需要 | 9 workspace crates | 后续候选；先拆 Pager 所需类型/路径 helper |
| `xai-grok-mermaid` | 非产品后端；属于可选原生渲染能力 | 18 | 可做可选 feature，但不是首批产品断连 |
| `xai-grok-voice` | 当前 grok-pi 明确保留 Pager voice | 21 | 不应默认剔除 |
| `xai-grok-sandbox` | 涉及安全/权限 | 28 | 未完成安全审计前不剔除 |

三项点名候选全部断连，静态 root graph 仅减少 **43/1296（3.3%）**。若继续断开 stock shell，约 **101/1296（7.8%）**；再拆掉完整 tools implementations，理论约 **174/1296（13.4%）**。若连 workspace runtime 一并收敛，组合静态上限约 **281/1296（21.7%）**。

## Evidence

### MCP

- `pi-grok-adapter` 对 MCP 只有工具名称注释，无 Grok MCP API 调用。
- External profile 不暴露 stock `/mcps`。
- 仍无条件编译 `xai-grok-mcp`，因为：
  - `xai-grok-config-types::mcp` 引用 `xai_grok_mcp::oauth_config::McpOAuthConfig`；
  - shell/workspace 的 MCP session、dispatcher、OAuth、doctor 模块无 feature gate；
  - Pager 的 MCP command/elicitation/headless 模块无 feature gate。
- 选取的 MCP 路径约 11k 行，即使运行时不可达仍编译。

### Plugin marketplace

- External command profile不提供 stock plugin/marketplace surface；Pi 资源由 `/pi-config` 与 Pi 自身 extension/package 语义管理。
- Pager + shell 中选取的 plugin/marketplace/CTA 路径约 14.4k 行。
- `event_loop.rs` 先以 `!external_agent` 禁用 `plugin_cta_enabled`，随后又无条件覆盖该字段；这是独立 runtime gate 漂移，实施断连前应先锁定测试。
- 该 crate 的大多数依赖已被其它路径共享，所以单删 marketplace crate 的 package-count 收益仅 1；真正收益来自同时 gate plugin modules、`xai-grok-agent` plugin path 和 tools implementations。

### Telemetry

- `run_external()` 仍构造 `xai_grok_telemetry::startup::PendingStartup`；Pager/shared shell 大量引用 event types、`session_ctx` 和 `unified_log`。
- Heavy engine 独占依赖包括 Sentry family、Mixpanel、secrets、tracing chrome/appender 等，共约 33 packages。
- 直接删除会破坏共享 Pager API；正确做法是同 API 的 no-op/light profile，把 heavy deps 置于 `product-telemetry` feature。

### Shell/tools umbrella

- `pi-grok-adapter` 对 `xai-grok-shell` 的真实使用仅集中于 config、workflow list/runtime、PersistenceMsg。
- `grok-pi.rs` 对 shell 的真实使用集中于 config 与 `host_features`。
- Pager 对 `xai-grok-tools` 主要消费 ToolOutput、Question/Plan DTO、SkillInfo、SessionMode、TaskSnapshot、MCP elicitation DTO 与纯 helper，却因此拉入完整 read/PDF/image/LSP/HTTP/computer-hub tool runtime及 build dependencies。

## Recommended slices

### S1 — `external-agent` build profile

在 composition package、Pager、minimal renderer、adapter 建立明确 feature contract。`grok-pi` 构建使用 external profile，stock `xai-grok-pager` binary 保持默认 product profile。先用 `cargo tree` 快照测试证明 feature 真的改变依赖图。

### S2 — MCP + marketplace hard gate

- 将 `McpOAuthConfig` 移至 config-types 或新的 leaf MCP-types crate。
- 将 shell/workspace/Pager MCP modules 和 dependencies 放入 `stock-mcp`。
- 将 plugin command/modal/CTA、shell plugin/marketplace modules 放入 `stock-plugins`。
- 修复并测试 External profile 的 duplicate `plugin_cta_enabled` 覆盖。

### S3 — telemetry light facade

保留 event DTO、startup handle 和 unified logging API；heavy Mixpanel/Sentry/OTLP client 全部 optional。external profile 使用 no-op event sink + local unified log。

### S4 — tools UI contract extraction

新增/复用 leaf types crate，迁移 Pager 所需 DTO 和纯 helper；External Pager 不再依赖完整 `xai-grok-tools` implementations。该切片预计是三项点名库之外最大的编译收益来源。

### S5 — shell/workspace runtime断连

将 config/host_features/workflow/persistence contracts移出 `xai-grok-shell`；然后 external Pager/adapter 取消 shell umbrella。再评估 Computer Hub、memory、session-search、stock auth/sampler 等随 shell 消失的依赖。

## Verification plan

```bash
cargo tree -p xai-grok-pager-bin --no-default-features --features grok-pi -e normal
cargo tree -p xai-grok-pager-bin --no-default-features --features grok-pi -i xai-grok-mcp
cargo tree -p xai-grok-pager-bin --no-default-features --features grok-pi -i xai-grok-plugin-marketplace
cargo tree -p xai-grok-pager-bin --no-default-features --features grok-pi -i sentry
./scripts/cargo-shared.sh check -p xai-grok-pager-bin --bin grok-pi --no-default-features --features grok-pi
```

每个断连切片必须同时验证 stock Pager 默认 build，避免为 grok-pi 优化时破坏上游产品 binary。

## Non-removable native core

`xai-grok-pager`, `xai-grok-pager-render`, minimal renderer、Markdown、diff、ACP、Ratatui/Crossterm、Pi adapter、配置/路径 leaf contracts属于唯一 TUI/adapter 核心。Voice 当前是明确产品能力；sandbox 属于安全边界，均不在首轮剔除范围。
