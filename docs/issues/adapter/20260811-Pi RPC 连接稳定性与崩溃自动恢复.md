# Pi RPC 连接稳定性与崩溃自动恢复

- 日期:2026-08-11
- 状态:进行中
- 范围:`pi-grok-adapter`(`pi_rpc.rs`、`pi_adapter/events.rs`、`pi_adapter/session.rs`)

## 问题

grok-pi 与 Pi 的 JSONL RPC 连接是一次性的:`grok-pi` 启动时 spawn 一个 Pi 子进程,之后:

1. **崩溃不可恢复。** Pi 进程意外退出时,`adapter_process_exit` 只做清理(取消排队/运行中的 prompt)并弹错误通知;`PiRpc` 的 writer 通道永久关闭,之后所有请求都失败,用户只能整个退出重启 grok-pi。
2. **挂死不可检测。** Pi 进程活着但事件循环卡死时,只有单请求 300 秒超时兜底,连接没有心跳,UI 长时间无反馈。
3. **无法区分主动退出与崩溃。** `rpc.kill()`(bootstrap 自愈、二分探针)与真实崩溃发出同一个 `adapter_process_exit` 事件,恢复逻辑无从判断是否应该重启。

## 方案

### 1. 可重连传输层(`pi_rpc.rs`)

- `PiRpc` 内部改为 `Arc<RpcShared>`:writer 与 child-control 发送端放入 `Mutex` 可置换;`pending` 表、事件发送端、`SpawnConfig` 常驻共享。
- 新增 `PiRpc::respawn()`:防御性 kill 现有子进程后,用启动时的 `SpawnConfig` 重新 spawn,并把新子进程的 writer/stdout/stderr/exit 协调任务接到**同一个** pending 表与事件通道上——`run_events` 循环与所有 `PiRpc` 克隆无感知地继续工作。
- `kill()` 先置 `intentional_exit` 标志;exit 协调器把该标志写进 `adapter_process_exit` 事件(`intentional: bool`),恢复逻辑只对 `intentional=false` 生效。
- 新增 `kill_unresponsive()`:不置标志的 kill,看门狗判定挂死后调用,让退出事件走正常崩溃恢复路径。
- 新增 `request_with_deadline()`:心跳等调用方可用短截止时间,超时即从 pending 表移除。

### 2. 崩溃自动恢复(`pi_adapter/events.rs` + `session.rs`)

`adapter_process_exit`(非 intentional)在既有清理后进入恢复流程:

1. 风暴护栏:5 分钟窗口内最多 3 次恢复,超过则停止自动重启并提示手动重启。
2. 退避重试(0.5s/1s/2s,最多 3 次):`rpc.respawn()` → 带 60s 截止的 `PiBootstrap::load` → `replace_bootstrap`。
3. 会话回接:若崩溃前 `session_file` 存在且文件仍在,`switch_session(session_file, 原 session_id)` 恢复原会话;失败则降级为新会话并明确提示。
4. `publish_bootstrap` + `refresh_context_usage` 刷新原生 UI(命令、模型、标题、上下文条)。

崩溃时已在途的 prompt/队列仍按 Cancelled 清理(不重放),恢复的是**连接与会话上下文**,不是在途轮次。

### 3. 挂死看门狗(`pi_adapter.rs` run_events)

- 每 15 秒发一次 `get_state` 心跳(15 秒截止),超时以类型化错误 `PiRpcTimeout` 区分。
- 仅统计"超时"型失败;"writer 已关闭"意味着进程已退出,由崩溃路径处理,不计数;RPC 错误响应证明进程仍活,同样清零。
- 连续 4 次超时(≈ 持续无响应 2 分钟,规避深树序列化等长同步段的误判)才判挂死:弹提示 → `kill_unresponsive()` → 复用崩溃恢复路径。
- 任意一次成功响应即清零计数;`PI_GROK_RPC_WATCHDOG=0` 可整体停用看门狗。

## 不做

- 不重放崩溃时在途的 prompt/队列(语义不明确,Pi 端可能已部分执行)。
- 不修改 Pi 源码、不新增 RPC 命令(仅用现有 `get_state`/`switch_session`)。
- 不在 Pager 侧新增 UI 面板;全部通过既有 toast(`pi/ui/notify`)与 bootstrap 广播呈现。
