# Configurable slash-command usage statistics + smart sorting

## Problem

The slash-command completion menu already ranks commands by recency (MRU), but this
behavior is not configurable and the statistics are recency-only:

- `SlashMru` (`crates/codegen/xai-grok-pager/src/slash/mru.rs:45`) stores one
  `command → last_used` timestamp per canonical command in `$GROK_HOME/slash-mru.json`
  (`store_path` at mru.rs:78, cap `MAX_ENTRIES = 256` at mru.rs:32). The doc comment is
  explicit: "one `last_used` timestamp per command, no use-count" (mru.rs:98-101).
- Recording is unconditional: `SlashController::record_command_use`
  (`crates/codegen/xai-grok-pager/src/slash/mod.rs:563`) → `touch` (mru.rs:173) →
  `persist_async` (mru.rs:289). Call sites: prompt submit
  (`views/prompt_widget/mod.rs:1380`, `app/dispatch/prompt.rs:635`) and dashboard
  dispatch (`app/dispatch/dashboard.rs:1511`).
- Ranking is unconditional in both sort paths:
  - Bare `/` menu: `MenuKey` (slash/mod.rs:104-136, recency field for the `Command`
    group only), stable sort at slash/mod.rs:1112.
  - Filtered input: tiebreaker chain at slash/mod.rs:1213-1223 (fuzzy score → exact
    typed name → `mru_scores` desc → Builtin over Acp → display), scores built at
    slash/mod.rs:1202-1208 via `rank_score`.

Users have no way to turn usage-statistics collection (a local file write) off, and
"smart sorting" ignores how often commands are actually used.

## Goal

1. A user-visible config toggle that turns slash-command usage statistics **and** the
   statistics-driven ranking on/off. When off: no reads, no writes of
   `slash-mru.json`, and both menus fall back to their static order (registry order in
   the bare menu; fuzzy → exact → Builtin → alphabetical in the filtered path).
2. Upgrade the statistics from recency-only to frequency + recency ("frecency") so the
   toggle actually delivers 智能排序 driven by real usage counts.
3. Surfaced in the native F2 settings modal (and automatically in the web-config host
   page via the baked F2 catalog).

## Design decisions

- **One bool gates both collection and ranking**: `[ui].slash_usage_stats`, default
  **on** (preserves today's recency behavior for existing users; the file stays local
  under the product-isolated `$GROK_HOME`, no new telemetry). Off is a hard gate: the
  store never loads the file and never writes it — the existing file is *not* deleted
  (data is preserved for re-enable; deletion is the user's call).
- **Statistics upgrade (frecency)**: extend the store to `{last_used, count}` per
  command and make `rank_score` frequency-weighted recency. Relevance still dominates:
  in the filtered path the fuzzy/exact tiebreakers stay *above* the stats term (only
  the `mru_scores` position in the existing chain changes meaning); in the bare menu,
  stats ordering stays confined to the `Command` group (skills remain alphabetical).
- **Scope alternative (rejected as default)**: a toggle-only change that keeps
  recency-only stats (no counts) is strictly smaller — skip Phase 2 below if the user
  prefers minimal diff. The toggle semantics in Phase 1 are identical either way.
- **Live apply**: the F2 def uses `restart_required: false` so toggling flips the
  shared store's enabled flag immediately (no restart, no lost ordering context).
- Naming: `slash_usage_stats` describes the privacy-relevant part (data collection).
  The setting description covers the smart-sorting effect.

## Tasks

### Phase 1 — config toggle + hard gate

1. `crates/codegen/xai-grok-shared/src/ui_config.rs`
   - Add `pub slash_usage_stats: bool` with `#[serde(default = "default_true")]` and a
     doc comment in the house style (what it gates: recording to
     `$GROK_HOME/slash-mru.json` **and** usage-based ranking; off → static ordering).
   - Add `slash_usage_stats: true` to `Default` (:514 area).
2. `crates/codegen/xai-grok-pager/src/slash/mru.rs`
   - Add an `enabled: bool` field (default `true`; `new_in_memory()` unaffected).
   - `set_enabled(bool)`: disable → clear in-memory state, mark loaded (never touches
     disk again); enable → reset `loaded` so `ensure_loaded` lazily (re)loads the file.
   - Gate `ensure_loaded` (skip the file read while disabled), `touch` (no-op, no
     dirty flag), `last_used`/`rank_score` (return 0) on `enabled`. Keep
     `persist_enabled` (test seam) orthogonal to `enabled` (product knob).
   - Unit tests: disabled store ignores an on-disk file and produces no snapshot;
     re-enable re-loads existing data; disabled `rank_score`/`last_used` return 0.

### Phase 2 — frequency statistics + frecency ranking

7. `slash/mru.rs` schema v2 (backward compatible):
   - `by_command: HashMap<String, CommandStat>` with `CommandStat { last_used: u64,
     count: u32 }`; deserialize the legacy flat `HashMap<String, u64>` into
     `last_used` with `count = 1` (never fabricate usage data); keep the read-only
     `by_prefix` migration; corrupt-file behavior unchanged.
   - `touch` bumps `count` saturating (practical cap, e.g. `10_000`).
   - `trim_to_cap` keeps evicting by `last_used` (recency), not count — rare-but-
     recent entries must survive, stale-frequent entries must not hoard the cap.
8. `rank_score` → frecency, documented and monotone:
   `recency_score(last_used, now) * (1 + ln(count))` in `f64` with explicit clamping;
   count ≤ 1 reduces to today's pure-recency score; never-used stays 0. Update the
   existing recency-decay tests and add ordering tests (recent-frequent > stale-
   frequent > recent-rare > never).
9. No changes required in slash/mod.rs sort chains — both already sort by
   `rank_score` output (:1107/:1206); verify the invariant tests from Phase 1 still
   pass with counts populated, and that existing controller tests
   (slash/mod.rs:2636, :2805) are unaffected (in-memory stores, counts start at 1).

## Constraints

- Architecture invariants untouched: no Pi source changes, no adapter changes, no new
  TUI surface — this is a native Pager setting wired through the existing F2 registry.
- Product isolation holds: state stays in `$GROK_HOME` (`~/.grok-pi`), never stock
  `~/.grok`.
- No destructive behavior: disabling never deletes `slash-mru.json`.
- Keep commits split per phase; the F2 catalog drift-guard test must stay green.

## Risks / open points

- `external_only` semantics for the new def (shell-owned vs external-profile-only) —
  verify against `SettingMeta` docs and existing shell-native settings before choosing.
- The `helpers.rs` apply arm's access to app state for live toggling — if unavailable,
  mirror the propagation path of another live-applied setting rather than adding a new
  global.
- frecency formula taste (log scaling vs linear cap) — log scaling is recommended so a
  single heavily-used command cannot permanently dominate the menu; the exact constant
  is easy to tune later because it lives in one function with tests.
