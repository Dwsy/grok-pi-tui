# OSC 7501 程序状态上报

## 问题

grok-pi 在支持 OSC 7501 的终端里不显示运行状态（working / blocked / done / error），原版 Pi 正常。终端标签只能看到 OSC 0 标题，看不到程序状态。

## 结论：Pi 的 RPC 模式根本不发这个协议

| 事实 | 证据 |
|---|---|
| 协议是 OSC 7501，不是标题 | `pi-main/packages/tui/src/program-status.ts` |
| 编码格式 | `ESC ] 7501 ; state=<s>[:app=<a>][:kind=<k>][:msg=<base64>] ST`，`state=clear` 清除 |
| 状态机只在交互模式实例化 | `pi-main/packages/coding-agent/src/modes/interactive/program-status-reporter.ts` |
| RPC 模式零调用 | `packages/coding-agent/src/modes/rpc/` 中 `rogramStatus` 无命中 |
| 扩展 API 不可达 | `core/extensions/types.ts` 只在弹窗的 `blocked?` 类型里引用 `ProgramStatus`，无上报方法 |
| 能力探测 | 启动发 `ESC ] 7501 ; ? ST`，终端回同样内容才算支持；`PI_PROGRAM_STATUS=1\|0` 可覆盖 |

所以「通过扩展 patch」这条路不存在：Pi 没有把 `setProgramStatus` 暴露给扩展，grok-pi 的 adapter 也无从转发。只能在 Pager（Rust 端）自己合成。

## 实现

状态来源复用标题已有的 `TitleState`，避免标题说 working、终端说 idle：

| 条件 | 上报 |
|---|---|
| `has_pending_permissions` | `blocked`，`kind=permission` |
| `is_busy` | `working`，`msg` = 会话名；`activity` 为 `AutoCompacting` 时 `msg=Compacting context` |
| 忙碌 → 空闲 | `done`；若该轮记录过失败则 `error`，`msg` = 错误首行 |
| 其余 | `idle` |

改动：

- 新增 `crates/codegen/xai-grok-pager/src/notifications/program_status.rs`
  - `format_escape`：编码、控制字符替换、2048 字节截断、空消息省略 `msg`
  - `ProgramStatusReporter`：状态推导、`done`/`error` 结算、去重、`clear`
- `notifications/mod.rs`：`on_tick` / `build_idle_escapes` 追加状态转义，`shutdown` 发 `state=clear`，`record_agent_error`
- `notifications/config.rs`：`program_status: bool`，默认 `true`
- `app/app_view.rs`：延迟队列里的 `AgentError` 通知写入失败状态

配置：

```toml
[ui.notifications]
program_status = true   # report idle/working/blocked/done/error to the terminal (OSC 7501)
```

## 取舍

- **不做能力探测**：Pager 没有终端查询回复的解析通道（`csi_filter.rs` 只处理 CSI，OSC 回复会漏成按键）。支持 7501 的终端显示状态，不支持的忽略未知 OSC。用配置项关掉作为兜底。
- **`error` 由通知路径记录**：`notify()` 保持 `&self`（`dispatch/status.rs` 借 `&NotificationService` 规避借用冲突），失败在 `app_view.rs` 延迟出队处以 `&mut` 记录。
- AX：标题（OSC 0）行为不变，两者同源。
