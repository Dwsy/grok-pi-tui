## 11. Herdr 快速状态变化丢失的 Red/Green 修复

- `extensions/pi-grok-herdr/index.ts` 原 `enqueue` 会将连续、尚未发出的 `pane.report_agent` 状态合并为最后一个请求。异步 Socket 应答前连续发生 `agent_start → herdr:blocked(true) → herdr:blocked(false) → agent_settled` 时，会把 `working → blocked → working → idle` 覆盖到只剩 `idle`。即使 Socket 和会话正常，Herdr 也无法观察已经被丢弃的生命周期状态。
- 在 `extensions/pi-grok-herdr/lifecycle.test.mjs` 增加真实 Unix Socket 上的快速事件连发测试，**修复前 exit 1**（`Missing Herdr report: working`，日志 `/tmp/pi-slim-herdr-rapid-red.log`）；移除无效状态覆盖、保留现有 `publish()` 同状态去重与 FIFO 顺序后，**exit 0**（日志 `/tmp/pi-slim-herdr-rapid-green.log`）。没有复制状态机，没有触碰 Herdr 源码。
- 注意：这项修复解决的是一次快速 turn 内的**状态丢失**，不能解释所有旧 Pane 未获得完整 hook authority 的原因。后者需要新编译产物进入真实 Herdr Pane 做实际受理验收，且不能仅凭 `idle` 显示判断。
