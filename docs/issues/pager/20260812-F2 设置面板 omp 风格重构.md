# 新 F2 设置面板（omp 风格，独立模块）

状态：已完成（待真机手测）
日期：2026-08-12
范围：新增 `crates/codegen/xai-grok-pager/src/views/pi_settings/`

## 背景

上游 F2 设置面板（`views/settings_modal/`）是单列平铺列表：顶部一条搜索栏，
下面按 `SettingCategory` 顺序渲染「分区标题 + 设置行」，描述靠 `←/→` 就地展开。
90 个设置全部堆在一列里，`Agent`（32 项）和 `Appearance`（25 项）需要长距离滚动。

参考实现是 oh-my-pi 的设置面板（`~/Dev/AI/oh-my-pi`）：

- `packages/coding-agent/src/modes/components/settings-selector.ts` —— 顶部 Tab 栏、
  全局搜索、footer 提示。
- `packages/tui/src/components/settings-list.ts` —— 左侧 section 侧边栏 + 右侧
  设置列表的分栏布局，非活动 section 整行变暗，底部固定 3 行描述区。

## Fork 约束（关键）

本仓库是 `xai-org/grok-build` 的 fork，`views/settings_modal/` 属于上游代码。
**重写上游文件会让后续 upstream 合并极难**（一次原型改动就动了 1400 行）。

因此本次采用与 `views/pi_config.rs`、`views/pi_models.rs`、`views/session_tree.rs`
相同的既有模式：**新增一个完全独立的 grok-pi 自有模块**，上游
`views/settings_modal/` 一行不改、代码保留、测试保持绿色。

## 设计决策

1. **独立模块**：`views/pi_settings/` 自己实现浏览列表、枚举选择器、字符串/数字
   编辑器、重置确认，不 `use` 任何 `views::settings_modal::*`。
2. **共用注册表**：`crate::settings::{SettingsRegistry, SettingMeta, SettingKind,
   current_value_for, …}` 是纯数据，继续复用——它是「有哪些设置」的唯一真相。
   动作映射（key → `Action::Set*`）在上游是 `pub(super)`，本模块自带一份。
3. **Tab = `SettingCategory`**，不新造分类维度；空分类不渲染 Tab。
4. **Section 是新增的一层**，落在 `pi_settings/layout.rs`：`section_for(key)` 加上
   每个分类的有序 section 列表。完整性由单元测试保证。
5. **复用原生 Grok Tab 栏**（`ModalWindowConfig.tabs`），与 `agents_modal` /
   `extensions_modal` 一致，Tab 用纯文本标签而非 nerd-font 图标。
6. **描述区从「就地展开」改为「底部固定 3 行」**，跟随焦点行；`←/→` 因此释放
   出来切换 Tab。
7. **键位沿用 Grok 习惯**（`j/k`、`g/G`、`/` 搜索、`d` 重置），只把 omp 的
   *布局* 搬过来，不搬它的「输入即搜索」——那会顶掉 Grok 既有的单字母键位。

## Esc 归属

模态框架（`modal_window`）默认把 Esc 当「关闭」。搜索、section 焦点与所有子面板
都需要 Esc 表示「退一步」，所以 `PiSettingsState::owns_escape()` 在这些状态下
先把键抢过来，`app/modals.rs` 据此绕过框架。`/` 之后即使查询为空也算搜索态——
光标已经在搜索框里，此时 Esc 只应退出搜索框。
`escape_belongs_to_the_panel_while_searching_or_focused_on_sections` 钉住这条契约。

## Group 行没有标量值

`SettingKind::Group`（`recap_models`、`btw_models`、`pi_builtin_tools`、`pi_config`、
`contextual_hints`）是纯导航行，注册表刻意不给它们 `current_value_for` 分支。
初版行绘制把「读不到值」一律当成注册表/派发错位，用 `accent_error` 打上
`(no read mapping)`，于是这 5 行在 Models / Agent / Advanced 三个 Tab 上全变成红字。

修正：行绘制先判 Group，画「标签 + 右侧 chevron」、值列留空；
`(no read mapping)` 只留给真正缺读映射的非 Group 行。
`group_rows_render_as_navigation_not_as_a_skew_marker` 钉住这条契约
（`external_only` 的两行受进程级 profile 开关约束，测试不翻它，绘制路径同一条）。

- `cargo check -p xai-grok-pager-bin --bin grok-pi`：通过（仅既有 warning）。
- 全量 `cargo test -p xai-grok-pager --lib`：本改动前 45 failed，改动后 50 failed；
  逐条比对后新增的 6 项与消失的 1 项全部落在 `scrollback::*` 与
  `app::mermaid_worker`，与设置无关，属于该测试套件既有的并行/全局状态抖动
  （见 `VERIFICATION.md` 的既知 baseline 维护项）。设置相关的三项失败
  （`defaults_match_ui_config_default`、`every_setting_has_action_for_reset_arm`、
  `rows_contain_categories_and_settings_through_pr_14`）在干净树上同样失败，
  原因是 `thinking_border_colors` / `pi_bash_run_display` 加入注册表时没有同步
  更新这些测试的基线，与本改动无关。

## 不变量

- 上游 `views/settings_modal/` 与 `Action::OpenSettings` 保持原样。
- `pi-grok-adapter` 不受影响；本改动完全在 Pager 内。
- 不引入第二套 TUI 组件：Tab 栏、模态框架、分隔线、搜索栏都走原生 Grok 组件。
