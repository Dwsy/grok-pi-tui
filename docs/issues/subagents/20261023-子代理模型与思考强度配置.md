# Issue: 子代理模型与思考强度配置（TUI + spawn 参数）

## Goal

让 grok-pi 子代理（V1 `spawn_subagent` 与 V2 team）可以显式指定**模型**与**思考强度**，并提供团队预设的**交互式配置界面**（`/subagent-teams`），使模型与思考强度可持久化到 project/global preset，而不是永远退化到 Pi 全局默认 `medium`。

## 背景/问题

代码事实：

- `extensions/pi-grok-subagents/runtime.ts:39-47` 的 `SpawnParams` 只有 `model`/`max_turns`，没有思考强度字段。
- `runtime.ts:416-425` 调用 `createAgentSession()` 时未传 `thinkingLevel`，导致 Pi 走 `pi-main/packages/coding-agent/src/core/sdk.ts:253-278` 的推导链，最终落到 `settings.defaultThinkingLevel ?? "medium"`（再被 `clampThinkingLevel` 钳制）。因此所有子代理的思考强度与任务需求无关。
- `extensions/pi-grok-subagents/definitions.ts:101-113` 解析 Markdown frontmatter 时不支持 `thinking_level`。
- `extensions/pi-grok-subagents/teams.ts:9-16` 的 `TeamMemberDefinition` 只有 `model`，没有 `thinking_level`；`/subagent-teams`（`v2.ts:95-109`）只做只读 `notify`，无法编辑。
- 仓库中不存在任何 model-facing 的"列出可用模型"工具（全仓 grep 无匹配）。

## 设计决策

| 决策 | 理由 |
|---|---|
| 思考强度枚举与能力推导放在新模块 `thinking.ts`，从 `model.reasoning` + `model.thinkingLevelMap` 就地计算 | Pi 没有把 `getSupportedThinkingLevels` / `clampThinkingLevel` 通过 extension API 导出；import `@earendil-works/pi-ai/compat` 会拉起全部 provider。10 行纯数据逻辑零依赖，且必须与 Pi `ai/src/models.ts:1240-1275` 语义一致。**唯一变化点隔离在一个文件**。 |
| `/subagent-teams` 从只读列表升级为完整 TUI，编辑结果写 project/global override | 与既有 `/subagents` 的 agent definition override 语义对齐（`config-ui.ts`）。bundled preset 不可原地修改，必须显式选择 override scope。 |
| **不注册任何 model-facing 工具**用于列出模型/思考强度 | 用户明确要求。所有发现能力只存在于 `ctx.ui.select()` 的选项里，模型上下文看不到。TUI 的选项文本本身即"列出的可用模型"。 |
| 模型选择默认「全部可用模型（默认）」 | 未指定 `model` 时保持 Pi 默认模型选择，不引入新的隐式限制。 |
| 思考强度默认「继承 Pi 设置」 | 未指定时不写 `thinking_level`，行为与改动前完全一致；显式指定才覆盖。 |
| runtime 侧对不支持等级执行 clamp，不抛错 | preset 是可能被他人分享的文件，硬失败会让整个 team 启动失败；Pi 自身也 clamp。实际生效值通过 bridge `spawned` 事件可见。 |

## 关键风险

- `thinkingLevelMap` 是 provider 可选字段；缺失时按 Pi 语义推导（`off..high` 全部支持，`xhigh`/`max` 不支持）。若推导偏离 Pi，会导致 TUI 选项与实际请求不一致。
- 编辑 preset 写盘使用原子替换（tmp + rename），与 `definitions.ts:saveDefinition` 保持一致，避免半写文件被 `parseTeamFile` 判为 malformed 而遮蔽低优先级 preset。
