# Issue: Codemode 原生渲染支持

## Goal

为 Pi `codemode` 工具在 Grok Pager 中提供专属原生渲染（Pi 风格卡片），并让 adapter 过滤
codemode 子调用的独立原生卡片行，统一实时会话与 resume 回放的表现。本 Issue 是 codemode
渲染实施的 SSOT；opt-in 接入（`pi_builtin_tools.codemode` → `--extension builtin:codemode`）
已在 `70c291aa` 落地，本 Issue 只覆盖渲染层。

## Pi Codemode 契约事实（依据 ~/.pi/pi 当前 checkout）

- 工具名 `codemode`，参数 `{ code: string }`；QuickJS 沙箱脚本通过 `tools.<name>()` 编排其他
  工具（`extensions/codemode/tool.ts`）。
- RPC 事件（`core/nested-tool-calls.ts`、`extensions/codemode/execute.ts`）：
  - `tool_execution_update.partialResult = { content: [], details: { calls: [...] } }`，每个嵌套
    调用 start/finish 时推送；
  - `tool_execution_end.result = { content: [header, ...输出 items], details: { calls, fullOutputPath? } }`。
- `CodemodeNestedCall = { id, name, args（截断 JSON）, status: running|ok|error|cancelled,
  durationMs?, error?, cost? }`；`cost` 来自 `models.classify` 等模型调用——这些调用不产生工具
  执行事件，只有卡内列表可见。
- 输出 header 固定为 `Script completed|failed\nWall time X.X seconds\nOutput:\n`；失败时输出
  以 `Script error:\n...` 结尾。
- 持久化 toolResult 同时含 `content`、`details`；**嵌套调用不产生独立历史条目**（只作为
  `nestedCalls` 记录在 toolResult 消息上）。
- 嵌套调用的 `tool_execution_*` 事件带 `parentToolCallId`（`agent-session.ts:182`）。
- Pi TUI 参考（`extensions/codemode/renderer.ts`）：卡内 = JS 语法高亮脚本 + 嵌套调用列表
  （状态字形 ✓✗…⊘、args 截 80 字符、耗时、cost、Model calls 合计）+ 剥 header 的输出预览；
  嵌套调用不渲染为独立工具行。

## 问题

- adapter `tool_kind("codemode")` 落 `Other`，Pager 渲染通用卡（标题 + 含 "Script completed"
  header 的原始输出文本）。
- 实时会话中每个嵌套调用被渲染成独立原生卡片行（adapter 未过滤 `parentToolCallId`），而
  resume 回放没有这些行（嵌套调用不在历史条目中）——live/replay 不一致。

## 决策

**Pi 风格卡片**：adapter 过滤 codemode 子调用的原生行（`parentToolCallId` 属于活跃
codemode 调用时抑制 ACP ToolCall 投射），单张 Codemode 卡内渲染脚本 + 嵌套调用列表 + 输出。
理由：与 Pi TUI 语义一致；修复 live/replay 不一致；`models.*` 费用只有卡内列表可见。

投影契约（adapter → Pager）：

- `raw_input.variant = "Codemode"`（与 `eval` 的 `"Eval"` 标记同模式）。
- `raw_output = { "type": "Codemode", "calls": [...], "output": "...", "full_output_path": "..." }`，
  覆盖 live end / live update / replay 三种输入形状；output 已剥离 header；Pager 在 output 为空
  时回退 `content_text`（回放 content）。

## 边界

- 不修改 Pi 源码 / RPC（架构不变量 5）。
- `codemode-store` custom entry（`store()`/`load()`）不在渲染范围。
- `eval_v2_only` 行为不变；其他工具的嵌套调用（`parentToolCallId` 非 codemode）不受过滤影响。
- 不把 `codemode` 加进 `ToolCallBlock::from_name`（与 Eval 一致；ACP 路径走 tracker variant 分支）。
