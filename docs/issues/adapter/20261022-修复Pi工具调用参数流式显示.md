# 修复 Pi 工具调用参数流式显示

## Goal

Pi 模型开始生成工具调用时立即在原生 Grok Pager 显示工具卡，并在参数 JSON 持续生成时更新 `raw_input`；工具开始执行后仍复用同一个工具调用 ID 与既有生命周期，不改变工具执行语义。

## Root cause (verified from source)

Pi RPC's `toJsonEvent` intentionally removes the cumulative `partial` assistant snapshot from `message_update`. For `toolcall_start`, it retains `contentIndex`, `id`, and `toolName`; for `toolcall_delta`, it retains `contentIndex` and the raw JSON `delta`; `toolcall_end` carries the canonical `toolCall`. The adapter currently ignores these three event kinds, so the first ACP tool card arrives only with `tool_execution_start`, after argument generation has completed.

## Acceptance criteria

- [x] `toolcall_start` publishes an in-progress ACP tool card immediately when the event contains its canonical Pi ID and name.
- [ ] Interleaved `toolcall_delta` events are accumulated by `contentIndex`, parsed best-effort, and update the same ACP card's `raw_input` without waiting for the full JSON object.
- [ ] `toolcall_end` publishes the final authoritative arguments; subsequent `tool_execution_start/update/end` events keep using the same ID and existing behavior.
- [ ] Hidden Eval-v2-only calls remain hidden; text/thinking streaming and existing tool output rendering are unchanged.
- [ ] Regression tests cover partial string/object arguments, malformed/incomplete suffixes, interleaved content indexes, and final-argument replacement where practical.

## Implementation plan

1. Add a dependency-free partial JSON object parser in the adapter model layer; prefer complete values and salvage the last complete top-level fields when the current suffix is incomplete.
2. Track streamed tool calls by Pi `contentIndex` in adapter state, emitting ACP `ToolCall` at start and `ToolCallUpdate.raw_input` as arguments grow.
3. Reconcile with canonical arguments at `toolcall_end`; clear stale stream state at message/turn boundaries.
4. Add regression tests, run adapter tests and the focused `grok-pi` check, and review the final diff.

## Constraints and decisions

- Keep Pi as the owner of tool IDs, execution, and lifecycle; do not patch Pi source or synthesize replacement IDs.
- Keep all visible UI native to Grok Pager; no second TUI and no broad renderer rewrite.
- Do not modify the pre-existing user change in `.github/workflows/macos-cargo-jobs-lab.yml`.
