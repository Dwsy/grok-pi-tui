# Issue: 扩展自描述 F12 与命令面板注册

## Goal

让 `extensions/*` 用自描述 JSON 声明 grok-pi 的 F2 设置项与 Cmd+P 命令面板投影；grok-pi 负责发现、校验、导入，Grok Pager 只消费通用注册数据并使用原生组件渲染，不再为每个扩展在 Rust 中维护 UI 元数据和坐标表。

## 背景/问题

当前 `HostFeatureManifest` 看似声明式，但 `HostFeatureSpec`、feature key、label/description/keywords、F2 section、默认值、启动环境和部分扩展源码均作为 Rust `static` 硬编码在 `xai-grok-shell/src/host_features.rs`。F2 的 section 还通过 `settings/layout.rs` 二次映射；Cmd+P 虽能从 ACP 动态追加 Pi commands，但扩展只能落入固定 `Pi / Extensions` 尾部，不能声明 section/order。新增或移动扩展 UI 仍需修改 Grok Rust，与扩展所有权不匹配。

## 验收标准 (Acceptance Criteria)

- [x] WHEN bundled extension 提供 grok-pi UI JSON，grok-pi SHALL 自动导入，不要求为该扩展新增 Rust feature spec/坐标常量。
- [x] WHERE F2 注册项来自 extension JSON，JSON SHALL 完整声明 `category/tab`、`section`、`order`、label、description、keywords、kind/default、restart 等渲染所需元数据。
- [x] WHERE Cmd+P 投影来自 extension JSON，JSON SHALL 声明 `section`、`order` 及目标 slash/action；只有真实可用命令才可投影。
- [x] IF JSON 存在重复 key、非法 category/section/order、非法 setting kind/default 或无效 palette target，THEN 启动/测试 SHALL fail fast 并指出来源文件。
- [x] WHEN stock Grok 不提供 external manifest，系统 SHALL 保持现有原生 settings/palette 行为不变。
- [x] WHEN extension setting 被修改，现有 `[ui]` 持久化、restart 语义、native feature conflict 与 startup env 行为 SHALL 保持一致。
- [x] WHEN extension UI 顺序变化，修改 JSON 坐标即可改变 F2/Cmd+P 排列，不需要编辑 Pager `layout.rs`/palette hardcode。
- [x] Verification SHALL 包含 manifest 解析/校验测试、F2 placement/order 测试、Cmd+P placement/order 测试及受影响 crate 的最窄 build/test。

## 关键决策

| 决策 | 理由 |
|------|------|
| 扩展 JSON 是 UI registration SSOT | 新增/移动扩展配置只改扩展目录，不把产品扩展清单复制进 Grok Rust。 |
| Pager 继续拥有渲染与交互 | 满足 Grok Pager 是唯一 TUI 的架构 invariant；JSON 只描述数据与坐标。 |
| 行为 hook 与 UI metadata 分离 | live cache、control-dir 等真实副作用仍可由 Rust 专用实现处理，但 label/坐标/默认展示不再硬编码。 |
| Cmd+P 仅投影真实 ACP command | 避免 JSON 生成不可执行的“幽灵命令”。 |
