## 阶段 1：移除 Pi 编译过程中未使用的 jemalloc

`xai-grok-pager-bin/src/main.rs` 是唯一为 stock Grok 安装 `#[global_allocator]` 的入口，`src/bin/grok-pi.rs` 不安装 jemalloc。此前共用包默认特性使 Pi 多编译 `tikv-jemalloc-sys`（上次 ARM64 该单元持续 173.7 秒）。

- Pi 的本地构建、发布构建与缓存预热使用 `--no-default-features`，但仍明确启用 `sandbox-enforce`。
- stock Grok 的包默认特性及全局分配器不变。
- CI 通过 `cargo tree -e normal,build` 断言三项 jemalloc 依赖均不可达，并编译真正的 ARM64 release 二进制；检查 `--version`、`--help` 与 `--print-capabilities`。
- **状态**：代码已提交前验证，CI 尚待运行。不预设实际 wall-clock 节省量。

### 第一轮 CI 失败与修复

- CI Run [43787682227](https://github.com/Dwsy/grok-pi-tui/actions/runs/43787682227)：jemalloc 依赖断言通过，`release-dist` 编译失败（`E0063`）。
- 编译失败来自基线 Pager 的 `PagerLocalSnapshot` 新增 `ask_user_question_timeout_secs` 后，5 处初始化器和启动期 App 配置镜像未同步，并非 jemalloc 裁剪引起。
- 修复将有效 TOML 中的正整数超时读取为 `Option<u64>`，在 App 中缓存，并传递到 dashboard、prompt、settings 的 5 个初始化器；无有效配置时交由 Snapshot 使用默认值，避免在热路径反复读取磁盘。
- 阶段仍须以修复提交对应的 ARM64 CI 成功为通过依据，不提前开始下一刀。
